## 1. 项目概述

### 1.1 一句话定位

把街机厅贴在屏幕旁的"出招表小抄"搬进电脑：一个**常驻桌面的轻量工具**，把你记录的连段**自动转换**成直观的图形化记法，**置顶悬浮**显示在格斗游戏画面上，练连段时随时可看。

### 1.2 背景与目标

- 你是多年格斗游戏玩家，目前处于入门→中级之间：连段以 3 招以内的简单组合为主，希望系统化提升连段熟练度。
- 痛点：
  1. 练连段时切出游戏查 wiki / 翻笔记，练习节奏被打断；
  2. 文本记法（DreamCancel 字母记法、数字记法等）读起来不直观，实战中来不及"翻译"。
- 目标：把"看到连段 → 理解每一步 → 手上搓出来"的循环做到**零切换、零翻译成本**。

### 1.3 本期范围

- **功能 A（本文档全部内容）**：连段小抄管理 + 记法自动转换 + 置顶悬浮显示。
- **功能 B**：你尚在构思中的第二个功能。本文档只在架构上预留接入位（见 FR-12），不做任何设计；你确定后再告知是否并入，届时另行补充文档。

### 1.4 非目标（明确不做）

- **不读取游戏内存、不注入游戏进程、不模拟按键输入**——纯展示工具，把作弊/封禁风险从设计上排除；
- 不做对战录像分析、帧数据数据库；
- 不做移动端版本。

## 2. 用户与使用环境

单用户、单显示器、本地使用、离线优先。

- **显示方式**：游戏以**无边框全屏**为主，偶尔**窗口模式**；两种都要支持。
- **输入设备**：**键盘**——按键图标以键盘键帽（keycap）风格为默认呈现（详见 FR-03 / FR-13）。

三个核心场景：

- **S1 训练模式练连段**：小抄半透明悬浮在画面角落（如右下），鼠标穿透不影响搓招；练熟一条按热键切下一条。
- **S2 录入连段**：从 DreamCancel wiki / 视频 / Discord 看到连段，把记法文本（如 `cr.B, cr.A, df+D(1), qcf+D, rdp+D`）粘贴进管理界面，保存后自动变成图形化小抄。
- **S3 对局间隙复习**：加载画面 / 选人界面瞄一眼当前页连段，上场就用。

## 3. 功能需求

优先级：**P0** = MVP 必须有；**P1** = 早期版本应有；**P2** = 后续打磨。里程碑归属见《任务计划》。

### FR-01 连段记录管理（P0）——独立管理器窗口（第五轮确认：双标签页）

- **独立管理器窗口**，分两个标签页：
  - **「导入」页**：选择游戏（拳皇 XIII / 拳皇 2002 UM）与角色（可新建；「全角色通用」连招在该游戏任何角色下都显示）；主体为连招信息录入——粘贴连段代码（DreamCancel / 数字记法均可）+ 标题（可选，留空自动命名 `Combo x`）+ 备注（可选），带实时预览。
  - **「展示」页**（两部分）：① **要显示的连招列表**——勾选「显示」才会上悬浮窗，点名称编辑、可删除；② **选项**——面板锁定、主题（A/C）、透明度、大小、表现形式（连招显示形式 / 按钮显示名）等，**默认折叠**，需要更改时展开；另有说明折叠区。
  - 所有修改自动保存，并即时同步到悬浮窗；**关闭管理窗口 = 退出整个程序**（第四轮确认）。
- 连段数据字段：游戏、角色、连段名称、起手条件、位置、标签、步骤原文、备注、显示开关、是否已掌握（起手条件 / 位置 / 标签暂未在界面提供，保留在数据结构中）。
- 支持关键词搜索与标签过滤（P1）。

### FR-02 连段录入与自动转换（P0，核心）

- 管理界面输入 / 粘贴记法文本，保存时自动解析为内部结构，悬浮窗渲染为图形化小抄。
- **MVP 内置两份记法档案**（覆盖你的两种输入习惯）：
  1. **「KOF · DreamCancel 记法」**：A/B/C/D 按钮体系；`cr.` / `st.` / `cl.` / `j.` 姿态前缀；`qcf` / `qcb` / `dp` / `rdp` / `hcf` / `hcb` 等指令词；`(N)` 帧数标注（如 `df+D(1)`）；KOF XIII 专属术语（HD 发动、Drive Cancel 等）与 2002UM 专属术语（MAX 发动等）分游戏配置。记法定义参考：[DreamCancel《KOF XIII/Controls》](https://www.dreamcancel.com/wiki/The_King_of_Fighters_XIII/Controls)。
  2. **「通用数字（numpad）记法」**：1–9 方向数字（含 `626` 这类常用写法）+ 按钮体系（KOF 下映射 A/B/C/D；SF6 下映射 LP/MP/HP…）。
  3. **「2002UM 攻略记法」（第六轮新增）**：`c5C` / `f5C`（近立 / 远立，无方向箭头）、`5`＝中立站立（不画箭头）、`•`＝同一必杀的派生键（如 `236D•D`）、`xxx`＝超杀取消、双按钮 `B+C`、`(N)` 段数标注（徽标只显示数字）、**空格与逗号均为步骤分隔符**。示例：`c5C xx 3D xx 63214B+C xx 236D•D, 421D`。参考：[Play More KOF 2002UM 攻略](https://playmorekof.blogspot.com/2020/10/king-of-fighters-2002-unlimited-match.html)。
- 两份档案解析结果汇入**同一套令牌流**，渲染完全一致（详见第 7 节）。
- 你后续提供的任何表示方式，以新增/扩充档案的方式接入，**不改核心代码**。
- SF6 档案、MK11 档案按需后补。注意 MK11 记法体系差异大（按钮用 1/2/3/4、方向用 F/B/U/D 缩写），届时单独设计。

### FR-03 图形化渲染（P0，核心）

悬浮窗连段信息的表示形式参考游戏内 Trial 界面的**横排 token 流**（参考图 `docs/design/reference-sf3s-online-trial-rows.png`）：**一行一整条连段**，token = 方向箭头 + 拳脚按钮块，尽量简洁、不遮挡画面。

- 一行 = 一条完整连段；面板内纵向排列多条连段。
- 方向 → **箭头图标序列**：qcf = `↓↘→`、qcb = `↓↙←`、dp = `→↓↘`、rdp = `←↓↙`、hcf = `←↙→`、hcb = `→↘↓↙←`；数字记法逐位转箭头（如 `26` = `↓→`）。
- 姿态映射为箭头前缀：`cr.` → `↓`、`j.` → `↑`、`st.` → 无前缀。
- 游戏按钮 → **彩色按钮块**（白字 + 按拳脚配色：LP 蓝 / LK 绿 / HP 橙 / HK 红；KOF 的 A/B/C/D 按档案映射为 LP/LK/HP/HK 显示，映射表可配置）。
- 步骤间以 `▶` 分隔；`xx` 取消 → `✕✕`；`>` 连携 → `≫`；`(N)` → 醒目的目押帧徽标（如 `1F`）。
- 超长连段自动折行；当前练习步骤高亮（P2）；后续按需增加其他表示形式（记法档案机制见第 7 节）。
- **容错原则**：无法识别的记号**原样显示并标黄提示**——宁可难看，不可丢字。

### FR-04 置顶悬浮小抄窗（P0）

- **黑底方块面板**：一块黑色半透明底板承载连段信息（游戏里看到的是干净的黑底方块），圆角细边框。
- 透明度可调（约 15%–95%）；大小可调（整体缩放）；可拖动定位，位置自动记忆；窗口置顶；默认**鼠标穿透**不影响操作。
- **锁定 / 解锁三重控制**（2026-09-28 第四轮确认）：
  - 面板右侧吸附一枚**小锁头图标**（独立小窗，永不穿透）——**任何状态下都可以点击**切换锁定；锁定 = 闭锁图标（穿透不可移动），解锁 = 开锁图标 + 蓝色高亮（可拖动）；点击不抢游戏焦点；
  - 管理器「⑤ 悬浮窗」区提供**「面板移动与否」**选项，与锁头图标、`M` 热键三处状态互相同步；
  - 锁定状态持久化，重启后保持。
- 配色两套、热键切换：**A 简约深色**（默认）与 **C 霓虹街机**（`T` 键切换）；黑底不变，仅边框 / 箭头 / 分隔符配色与光效变化。
- 显示内容 = 当前游戏 / 角色下的连段列表（每行一条）；数据变化后热键即时重载。

### FR-05 鼠标穿透与模式切换（P0）

- 默认**穿透模式**：鼠标点击穿过小抄落到游戏上，不抢焦点、不影响操作。
- 托盘菜单或热键切换"管理模式"（此时可拖动 / 设置），用完自动回到穿透。
- 窗口失焦自动回到穿透模式（防呆）。

### FR-06 全局快捷键（修订——第五轮确认）

- **仅保留 `Ctrl+Alt+Q`（退出程序）** 一个全局热键；不使用任何单键全局热键（避免打字时误触发、吞键）。
- 悬浮窗的所有状态调整（显隐、锁定、主题、透明度、大小、重载数据）全部经由管理器窗口或面板右侧的锁头图标完成。
- 悬浮窗下方**不再显示说明文字**（相关说明移至管理器「展示」页的折叠区）。

### FR-07 数据存储与备份（P1）

- 本地 JSON 文件库（人类可读、可手动编辑、可放进网盘 / git 备份）。
- 导入 / 导出 JSON；自动备份最近 N 份（写前轮换）。
- 防丢数据：修改即写临时文件 + 原子替换，崩溃 / 断电不损坏库文件。

### FR-08 多游戏档案（P1）

- 游戏 → 记法档案 + 术语表 + 按钮命名体系，均可按游戏配置。
- 首发游戏配置：**拳皇 XIII、拳皇 2002 UM**（两者共享基础词法，术语层各自独立）；SF6、MK11 配置文件后补。
- 新游戏 = 新配置文件，零代码。

### FR-09 游戏内可见性（P0，约束性需求）

- 以**无边框全屏**为主要验证目标；**窗口模式**天然可见，一并测试。
- **已知限制**：游戏若用"独占全屏"，普通置顶窗口会被画面覆盖。处理方式：使用说明引导切到无边框全屏；M0 阶段在 KOF XIII / 2002UM 上实测验证。

### FR-10 键位映射（P2，暂缓——已确认先显示按钮名）

- 已确认：暂不需要显示实际键盘键位，按钮块直接显示游戏按钮名（LP/LK/HP/HK，KOF 的 A/B/C/D 映射而来）。
- 保留能力（后续可选）：游戏按钮 → 键盘按键映射表（按游戏独立），支持把按钮块切换成实际键帽样式。

### FR-11 主题与观感（P2）

- 四套主题（设计稿 `docs/design/`：A 简约深色 / B 简约浅色 / C 霓虹街机 / D 街机柜红金）；字体大小、行距、图标大小可调。

### FR-12 系统集成（P2）

- 托盘图标与菜单；开机自启（可选）；单实例运行。

### FR-13 第二功能预留位（P2，仅架构）

- 主界面导航与模块结构预留一个接入位与模块注册机制；功能 B 确定后可平行接入，也可独立成应用，互不影响。

## 6. 数据模型（草案）

存储：`data/combos.json`（便携版数据目录位于程序目录内）。示例：

```json
{
  "version": 1,
  "games": {
    "kof13":     { "name": "拳皇 XIII",      "notation": "dreamcancel-kof", "termGlossary": { "HD": "Hyper Drive 发动", "DC": "Drive Cancel" } },
    "kof2002um": { "name": "拳皇 2002 UM",   "notation": "dreamcancel-kof", "termGlossary": { "MAX": "MAX 发动" } },
    "sf6":       { "name": "Street Fighter 6", "notation": "numpad-generic",  "termGlossary": { "DR": "Drive Rush（绿冲）" } },
    "mk11":      { "name": "Mortal Kombat 11",  "notation": "mk-standard" }
  },
  "keybinds": { "kof13": { "A": "U", "B": "I", "C": "O", "D": "P" } },
  "combos": [
    {
      "id": "kof13-001",
      "game": "kof13",
      "character": null,
      "name": "版中基础连段",
      "condition": "确反机会",
      "position": "midscreen",
      "tags": ["基础"],
      "mastered": false,
      "raw": "cr.B, cr.A, df+D(1), qcf+D, rdp+D",
      "steps": [
        { "t": "move", "stance": "cr", "button": "B" },
        { "t": "move", "stance": "cr", "button": "A" },
        { "t": "move", "motion": "df", "button": "D", "link": "1F" },
        { "t": "move", "motion": "qcf", "button": "D" },
        { "t": "move", "motion": "rdp", "button": "D" }
      ],
      "notes": "",
      "createdAt": "2026-09-28T12:00:00+08:00",
      "updatedAt": "2026-09-28T12:00:00+08:00"
    }
  ]
}
```

设计要点：

- **`raw` 记法原文永远保留**；`steps` 由解析器生成，仅作渲染缓存。记法档案升级后可一键全库重解析，信息零丢失。
- `character` 为 `null` 表示全角色通用连段。
- `df+D(1)` 中的 `(1)` 目押帧标注会被解析为独立的 `link` 字段，渲染成帧数徽标（其精确语义以 DreamCancel 页面核对后定稿）。
- 示例连段内容仅演示数据格式。

## 7. 记法转换引擎（核心设计）

流水线：**输入文本 → 词法解析（按记法档案）→ 令牌流（IR）→ 渲染器 → 图形 / 文本**

**两条输入路线，一套令牌流**：DreamCancel 字母记法与数字记法各自有解析规则，但汇入同一个 IR（`df` 与 `3` 都解析成"斜下方向"，`qcf` 与 `236` 都解析成"四分之一圈前"），因此渲染结果完全一致——你两种写法混着用都没问题。

| DreamCancel 写法 | 数字记法 | 含义 |
|---|---|---|
| `qcf` | `236` | 四分之一圈前（波动） |
| `qcb` | `214` | 四分之一圈后 |
| `dp` | `623` / `626` | 升龙指令 |
| `rdp` | `421` | 反向升龙 |
| `hcf` / `hcb` | `4126` / `63214` | 半圈前 / 半圈后 |
| `df` / `db` / `uf` / `ub` | `3` / `1` / `9` / `7` | 斜方向 |
| `cr.` / `st.` / `cl.` / `j.` | 蹲 / 站 / 近站 / 跳 | 姿态前缀 |
| `(N)` | — | 目押帧标注（渲染为帧数徽标；精确语义以 DreamCancel 页面核对后定稿） |

- **记法档案（数据文件，YAML/JSON）**：每"游戏 × 风格"一份，包含别名表、指令符号表、按钮集合与配色、连接符定义、术语表；你后续提供的任何写法写进档案即可。
- **容错原则**：任何解析不了的片段原样透传并高亮标注，绝不静默丢弃步骤。
- **渲染器可插拔**：同一份令牌流可渲染为"图形 token 流"（默认）、"纯文本"（P2），为将来记法互转留口子。
- **接入你未来的表示方式** = 编写 / 扩充一份档案文件，不动代码（M2 阶段提供档案编写指南，或由我代写）。
