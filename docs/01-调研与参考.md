# FTG-Overlay 调研与参考

调研日期：2026-09-28　|　范围：GitHub、crates.io、社区（Reddit r/fighters、r/fightsticks）

## 一、结论先行

在 GitHub 与社区检索后，**没有发现与"自建连段小抄 + 记法自动图形化 + 游戏内置顶悬浮"完全重合的现成工具**。最接近的两个项目各自只覆盖其中一块：

- **soupTrainer**：有"悬浮在游戏上的连段提示"，但做的是节奏游戏式的逐帧定时回放，不是随看随练的出招小抄；
- **fg-input-translator**：有"记法 → 图形化"，但只是个网页转换器，无连段库、无悬浮窗。

=> 自研有价值，且两者（外加若干悬浮窗项目）的实现思路可以直接借鉴。

## 三、定位差异（一句话版）

现有工具要么**考核你**（判定输入、节奏回放），要么**转格式**（纯转换器），要么是**不懂记法的小抄**（手动贴文字，无图形化）。本项目的独特组合 = **你自己的连段库 + 记法理解与图形化 + 游戏画面前置顶常驻**——一个"会读连招的电子出招表"。

## 四、可直接借鉴的具体决策

1. **图形渲染**：参考 fg-input-translator 的 SVG 图标库组织方式（`Motion236.svg`、`ActionAnyPunch.svg` 这类按 token 命名的图标资产）。
2. **数据格式**：参考 soupTrainer 的分段式连段文件思路，但我们改用结构化 JSON，并且**永远保留记法原文**，转换结果只作为可重算的缓存。
3. **悬浮窗**：置顶 + 分层窗口 + 鼠标穿透（`WS_EX_TRANSPARENT | WS_EX_LAYERED`）是 Windows 成熟做法，OmniWatch / soupTrainer 都验证过可行；soupTrainer 需要第三方置顶工具的教训 → 本项目 M0 阶段必须验证原生置顶稳定可用。
4. **记法扩展**：新记法/新游戏以"档案数据文件"接入而非改代码（借鉴 fg-notation 的模块化翻译思路）。

## 五、检索方法备注

使用的关键词（英文为主、中文为辅）：`combo trainer overlay`、`numpad notation converter`、`move list overlay`、`training mode tool`、`cheat sheet overlay`、`fighting game notation translator` 等。你的主要游戏确定后，值得再做一轮**针对该游戏的专项检索**（专用训练 mod / overlay / 记法约定），避免重复造轮子并校准默认记法。
